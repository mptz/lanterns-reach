# Build notes — v0.1 point releases (history)

The build agent's notes for v0.1 through v0.1.9, moved from
`BUILD-NOTES.md` when v0.1 closed. **History, not authoritative:** the
code is the reference for current behaviour.

## v0.1 (built 2026-10-28)

### Build & run
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug && cmake --build build
./build/sandbox
```
Ubuntu 24.04 packages used: `cmake ninja-build libvulkan-dev
vulkan-validationlayers vulkan-tools glslc glslang-tools spirv-tools
libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev libxkbcommon-dev
libwayland-dev wayland-protocols` (+ `xvfb` and `x11-apps`/`imagemagick` for

### Coordinates / winding
- View space is **x right, y down, z forward**. It is right-handed, like the
  z-up RH world, so world→view is a proper rotation (rows = camera right,
  down, forward; `Camera::view()`). The hand-built projection keeps view +y =
  clip +y, which is Vulkan's y-down convention, so the transform has **no axis
  flips**.
- So the cube's triangles, CCW seen from outside (right-hand rule gives the
  outward normal), stay CCW in Vulkan framebuffer space:
  **`frontFace = COUNTER_CLOCKWISE`, `cullMode = BACK`**. I verified this on
  lavapipe from above and from below/behind. The debug normal view also shows
  each face's normal on the expected screen side (no mirroring).
- The projection is hand-written (`Camera::projection`): standard depth with
  0 at near and 1 at far, no reverse-Z, near 0.05, far 1000.
  `GLM_FORCE_DEPTH_ZERO_TO_ONE` / `GLM_FORCE_RADIANS` are still defined as
  specified.
- Camera yaw is about world +z (0 = looking east), with pitch clamped to just
  under ±90°. Mouse right = yaw decreases (turn right). WASD moves along the
  full 3D look direction.
- The cube is 1 unit (≈ 1 ft) on a side, centered on `WorldPos(0,0,0)`. The
  camera starts at (−3.5, −2.5, 2.2) looking at it.

### Rendering choices
- Light (retuned 2026-10-28 after on-GPU review found faces too similar):
  `L = normalize(0.187, 0.463, −0.867)` (the direction light travels), ambient
  **0.10**, directional 0.90. The first values (`L ∝ (0.4, 0.7, −1)`, 0.15 /
  0.85) gave linear face factors 0.41 / 0.61 / 0.81, but after the sRGB encode,
  which compresses highlights, those display as 0.68 / 0.81 / 0.91: steps of
  only 0.11–0.13. The new values are chosen for evenly spaced *displayed*
  brightness. Linear factors are 0.10 (+x/+y/−z, ambient only) / 0.27 (−x) /
  0.52 (−y) / 0.88 (+z), which display as about 0.35 / 0.55 / 0.75 / 0.95.
  The three faces turned away all get the same ambient level; a single
  directional light can't separate them. Ambient is 0.10 rather than the
  spec's "~0.15" to widen the range; away-facing faces stay visible.
- Tonemap: **clamp** (allowed by the spec). The background is linear
  (0.02, 0.03, 0.05).
- G-buffer reads use `texelFetch` with a nearest/clamp sampler. All sampled
  images, depth included, use `SHADER_READ_ONLY_OPTIMAL`.
- Debug views 3/4 are converted to linear before output, so the sRGB
  swapchain encode puts the exact value on screen: normal = N·0.5+0.5, and
  depth = linear z / 12 units (background shows white).
- Texture: nearest filtering, repeat addressing, no mipmaps. `assets/block.png`
  is a 32×32 brick texture generated by `tools/gen_block_texture.py` (stdlib
  only), with a red top-left marker that shows face orientation. If the file
  is missing, a generated checker is used instead. The asset path is compiled
  in as an absolute path (`SANDBOX_ASSET_DIR`).
- SPIR-V is compiled at build time with `glslc -mfmt=num` and `#include`d
  into the binary, so there are no runtime shader files.

### Render-graph seam (`src/render_graph.*`)
- Passes declare color/depth attachments, sampled images and copy
  destinations. The graph emits every `vkCmdPipelineBarrier2`, the only call
  in the codebase, and wraps attachment passes in `vkCmdBeginRendering`.
  It also emits the one-time texture upload's transitions (a transfer pass).
- Image state (stage/access/layout) lives with the image and **persists
  across frames**. That covers the hazard where frame N+1 overwrites a
  G-buffer target that frame N is still sampling (2 frames in flight, one
  shared G-buffer).
- **Sync-validation finding:** the final `→ PRESENT_SRC` transition with
  `dstStage = NONE` raised `SYNC-HAZARD-PRESENT-AFTER-WRITE`. It now uses
  `dstStage = COLOR_ATTACHMENT_OUTPUT`, which is inside the `ALL_COMMANDS`
  scope of the render-finished semaphore signal, so the transition is ordered
  before present.
- Render-finished semaphores are allocated per swapchain image, not per frame
  in flight, to avoid reusing a semaphore while a present still holds it.
  Swapchain-sized targets and descriptors are recreated on out-of-date,
  suboptimal or resize events (after `waitIdle`).

### Test-harness additions (not in the v0.1 spec; small, for scripted runs)
- CLI flags: `--frames N`, `--view N`, `--cam X Y Z`, `--resize-at N W H`.
- Env var `SANDBOX_GLFW_PLATFORM=x11|wayland`. GLFW 3.4+ prefers Wayland
  whenever a compositor socket is reachable, even with `WAYLAND_DISPLAY`
  unset, so the X11 platform has to be forced to run under Xvfb.
- `tools/headless_check.sh`: runs every debug view, a below/behind camera and
  a resize on Xvfb + Mesa **lavapipe**, screenshots each, and fails if any
  run reports a validation error. Screenshots go to `build/headless/`.
  Intel ANV can't present on Xvfb (it needs DRI3), so real-GPU checks need the
  real display.

## v0.1.1 (built 2026-10-28)
- Each block is a `Renderer::Block`: f64 `WorldPos` + its own `Texture` + its
  own descriptor set. The G-buffer pass binds the set, pushes the MVP and
  draws once per block. The blocks are declared after the descriptor pool, so
  their sets are freed before the pool is destroyed.
- All block textures are imported into the frame graph as sampled reads. They
  persist in `SHADER_READ_ONLY` from their upload, so they add no per-frame
  barriers.
- `tools/gen_block_texture.py` now writes all four textures. The brick output
  is byte-identical to v0.1's. Grass and dirt are tileable value noise plus
  speckle; stone is two noise octaves plus thin dark veins.
- The headless check's below/behind camera moved to (4.5, 4.0, −1.5) to clear
  the larger group.
- Status: headless suite passes (zero validation errors, sync validation
  included), and the layout and textures are verified in lavapipe
  screenshots. Confirmed by a human on the GPU + display (2026-10-28).

## v0.1.2 (built 2026-10-29)

### Build, test & run
```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug && cmake --build build
ctest --test-dir build          # headless: no GPU or display needed
tools/headless_check.sh         # lavapipe + Xvfb screenshots and validation runs
./build/sandbox
```
Controls: mouse look, WASD, **C/V** = world up/down, **Ctrl** (either side)
= 4× speed. **Esc** releases the mouse; Esc while it is released quits; a
left-click recaptures. Losing window focus still releases, as in v0.1. **F1**
toggles the stats overlay, **F2 / Shift+F2** cycle the buffer view forward
and back, and **F3** toggles the wireframe. E, Q, Tab, Shift (alone) and
the number keys do nothing. New harness flags: `--stats` and `--wireframe`
start with F1 / F3 on.

### Choices
- **Version label:** one source. `project(sandbox VERSION 0.1.2)` feeds
  `SANDBOX_VERSION="v0.1.2"`, which the window title, the Vulkan app name
  (plus `applicationVersion` 0.1.2), the startup line and F1 all use. The
  CMake project name changed from `sandbox_v01` to `sandbox`.
- **Validation:** Debug builds check `vkb::SystemInfo::validation_layers_available`
  in `main()` *before* `glfwInit`, print `[sandbox] validation: on|off`, and
  exit 1 if the layer is missing. The check needs no display, so it is also
  a CTest (`validation_missing_fails`, Debug only), run under
  `VK_LOADER_LAYERS_DISABLE=~all~`. The instance then uses
  `enable_validation_layers(true)`, so the layer is *required* and instance
  creation fails rather than silently falling back. Release builds print
  `validation: off` and don't request the layer.
- **Dear ImGui v1.93.0** (newest release) is built as a static `imgui`
  library from its sources plus `imgui_impl_glfw` / `imgui_impl_vulkan`. It
  uses dynamic rendering (`PipelineInfoMain.PipelineRenderingCreateInfo`)
  and its own descriptor pool (`DescriptorPoolSize`). `src/dev_ui.*` wraps it.
  - ImGui's style colors are sRGB values. The swapchain is sRGB and encodes on
    write, so the colors are converted to linear once at startup; otherwise
    the UI comes out washed out.
  - `io.IniFilename = nullptr`, so no `imgui.ini` is written to the working directory.
  - While the mouse is captured, `ImGuiConfigFlags_NoMouse` is set. The GLFW
    backend still feeds a disabled cursor's motion to ImGui, so without this
    the hidden cursor could hover or click dev windows.
  - Game input ignores the keyboard while `WantCaptureKeyboard` is set. A
    left-click while released recaptures only if ImGui doesn't want the
    mouse, so clicking a dev window interacts with the window instead.
  - Its GLFW callbacks are installed after the app's and chain to them.
    `~DevUi` restores the app's callbacks before the window is destroyed.
  - **Exception to "barriers only from the seam":** when its font atlas
    changes (in practice the first frame only), `ImGui_ImplVulkan_RenderDrawData`
    records its *own* command buffer with `vkCmdPipelineBarrier` and does a
    `vkQueueSubmit` + `vkQueueWaitIdle` for the upload. That is third-party
    setup code on ImGui's own image, not our pass code, and it runs outside
    our frame command buffer. Our UI pass itself only issues draw calls.
- **UI pass:** it is the last graph pass, drawn onto the swapchain image with
  `load = LOAD` at the swapchain's extent (native resolution, DPI scale from
  `glfwGetWindowContentScale`). The graph emits the color-attachment
  write→write barrier between present / wireframe / ui.
- **Recapture click:** both the press *and* its release are swallowed (the
  release arrives while already captured). The captured mouse-button branch
  in `onMouseButton` is where v0.1.5's intention layer will hook in.
- **Per-pass GPU time:** owned by the render-graph seam.
  `RenderGraph::timePasses(pool)` resets the pool and writes an
  `ALL_COMMANDS` timestamp pair around each pass (barriers included). Each
  frame in flight has its own 16-query pool. Results are read after that
  frame's fence wait, so F1 shows the most recently *completed* frame (one
  frame-in-flight late), raw and unsmoothed. Tick deltas are masked to
  `timestampValidBits` and scaled by `timestampPeriod`. If the graphics
  queue has 0 valid bits, no pools are created and F1 shows "n/a".
  FPS / frame time are averaged over 0.5 s windows.
- **F3 wireframe:** the cube's 12 edges are a line list. `cube::edgeIndices()`
  indexes the existing 24 vertices, with shared edges deduplicated. They are
  drawn after the present pass, onto the swapchain, in linear
  (1.0, 0.75, 0.1). Depth testing is **manual**: the fragment shader
  compares `gl_FragCoord.z` against the sampled G-buffer depth and discards
  behind it. So there is no depth attachment and the graph needs no
  read-only-depth mode yet. **Bias:** positions are camera-relative, so the
  camera sits at the origin. Scaling each position by `1 − 0.002` pulls it
  toward the eye by 0.2 % of its distance. That keeps edges in front of
  their own faces at every range, and hidden back edges (≥ ~1 unit behind
  the front faces) stay hidden out to a few hundred units. Lines need no
  `fillModeNonSolid`.
- **Exact sRGB:** the debug normal/depth views pre-linearize with the exact
  sRGB EOTF, not pow 2.2. Verified on lavapipe: the top face's normal,
  (0.5, 0.5, 1), reads back as (127, 127, 255).
- **Tests** (`ctest`): `sandbox_tests` (in-house `CHECK`, `tests/check.h`)
  checks that `rebase()` is exact at ±1e9 (offsets 0.25 / −0.5 / 0.125). Its
  documented counterexample shows that downcast-first gives 0, because f32
  spacing at 1e9 is 64. `gen_block_texture` runs the tool into a non-existent
  nested directory and checks that the output is byte-identical to `assets/`.
  `validation_missing_fails` is described above. The Python checks run with
  `python3 -I`.
- `tools/headless_check.sh` adds two runs with F1 + F3 on, turns the overlays
  on for the resize run, and adds the no-validation-layer run (Debug).

## v0.1.3 (built 2026-10-29)

### Build, test & run
As in v0.1.2. `ctest --test-dir build` now runs 10 tests (Debug) / 9 (Release).
New flags: `--orientation` (start with F4 on), `--look X Y Z` (look-at
point for scripted views), `--blocks DIR` (definitions directory, default
`assets/blocks`), `--check-blocks` (load the definitions, report, exit; no
window). **F4** toggles the orientation overlay, and F2 now cycles five
views (… → depth → material id).

### Layout
- `src/orientation.*`: the group, tables, the 11 types, orbits and
  canonicalization. Pure integer math, no Vulkan.
- `src/blocks.*`: the JSON loader, PNG decode, `BlockState`, and the
  registry. Together with orientation and `stb_impl` this is the CPU-only
  `sandbox_core` library, which the engine and `sandbox_tests` both link.
- `src/scene.*`: the hardcoded test placements.
- `assets/blocks/`: the definitions (`*.json`) **and** their textures. Texture
  paths are relative to the definition's directory. The four v0.1.1 PNGs
  moved here from `assets/`, and `block.png` was renamed `brick.png`.
- `tools/validate_blocks.py`: the validator, standard library only.
  `tests/blocks_bad/{wrong_keys,asym_side}/`: the negative fixtures.

### Choices
- **Rotation indexing:** `r = 4·facing + spin` = F(facing)·R_z(90°·spin).
  `facing` is where local +z goes, in the representative order
  +z −z −y +y +x −x, so index 0 is the identity. F is I, R_x(180°),
  R_x(90°), R_x(−90°), R_y(90°), R_y(−90°). Canonical indices of `column` /
  `pointed` come out as multiples of 4. The test scene's logs are z-axis 0,
  y-axis 8, x-axis 16. Its furnaces are 0, 1, 2, 3 (front −y, +x, +y, −x),
  12 (facing up), 8 (facing down).
- **Turn convention:** `faceTurns[g][n]` and the material table's turns are
  counter-clockwise quarter turns *as seen from outside the face*.
  `rotateCcw` (C++ and Python) follows the same convention: CCW takes the
  top-left corner to the bottom-left. Tests check that turns compose
  (`turns(a·b, n) = turns(b, n) + turns(a, b·n)`).
- **Rendering a rotation:** the vertex shader rotates the cube's positions and
  normals by the rotation table's matrix. The geometry carries every face's
  texture rigidly, so placement needs no per-orientation texture logic. The
  material table only applies the *definition's* frame mapping. Each local
  face gets its orbit representative's layer, turned by the lowest-index
  h ∈ H that carries the representative onto it. The stabilizer-invariance
  check guarantees any other h would look the same. `sandbox_tests` checks
  that rendering with g or with g·h gives identical world faces.
- **Material id = block type id + 1.** Id 0 is "no material", GB3's clear
  value, shown black in the material view. The material table is a
  host-visible SSBO of 8 uints per material (6 used: `layer | turns << 16`).
  The 24 rotation matrices are a second SSBO (`mat4`, std430). Push
  constants are mvp + rotation index + material id (72 bytes).
- **Texture array:** every definition texture becomes one layer of a single
  `R8G8B8A8_SRGB` 2D array, with no mips and nearest filtering. Layers are
  deduplicated by file path. All textures must share one size; a definition
  that breaks this is rejected.
- **Textures must actually have their declared symmetry, so the four v0.1.1
  textures were regenerated** to be 4-fold rotation symmetric (they're
  `uniform` now). Noise is the average over each pixel's 4 rotations, summed
  in a fixed order so the result is bit-identical. Speckle is a hash of the
  orbit's canonical pixel. The brick is a **pinwheel bond** (four 20×12
  bricks around an 8×8 square), the brick layout with 4-fold rotation
  symmetry. The red orientation marker is gone; the furnace now carries
  that role.
- **Furnace faces** each have a chiral letter in their top-left corner (F
  front, B back, R right, L left, U top, D bottom). The front has an
  opening, and the top has an arrow pointing to the front. A wrong turn or a
  mirror shows as a misplaced or backwards letter.
- **Loader policy:** definitions load *before* GLFW, so `--check-blocks` and
  the rejection CTests need no display. A rejected definition is skipped
  with an error, and Debug builds then refuse to run (exit 1), as specified.
  Release builds run without it, and its placements are skipped with a
  warning. Unknown JSON fields are rejected so typos surface; v0.1.4 will
  add `roughness` etc. to the allowed set.
- **Cross-check:** `sandbox_tests --dump-orbits` and `validate_blocks.py
  --dump-orbits` print the subgroup orders, orbits, representatives and
  stabilizer turns. The Python side is an independent implementation. The
  `orbit_tables_agree` CTest requires the two outputs to be identical.
- **F4:** axes are 1-unit lines from each block center along its *stored*
  (canonical) rotation's local x/y/z, colored red/green/blue. Only the
  outer half shows outside the cube. They share one debug-line pass with
  F3: a CPU-built, camera-relative vertex list in a per-frame host buffer,
  replacing v0.1.2's separate wireframe pipeline. Labels are ImGui
  foreground text above each block: name, symmetry keyword, `#canonical`,
  plus `(placed #g)` when the placement rotation differs (e.g. the fourth
  log: `column #0 (placed #1)`).
- **Start camera** moved to (5, −12.5, 4.5) looking at (5, −2, 0), north over
  the furnaces and logs to the v0.1.1 group. From there dirt is still right
  of brick, and stone/grass are behind them.
- **nlohmann/json v3.12.0** (newest), `FetchContent`, `JSON_BuildTests` off.

## v0.1.4 (built 2026-10-29)

### Build, test & run
As before; `ctest` runs 14 tests (Debug) / 13 (Release). New controls:
**F5** toggles the lighting overlay: light positions with radius spheres,
the light-count heatmap, and the lighting panel. Release the mouse (Esc)
to use the panel's sliders. F2 now cycles six views (… depth →
roughness/metallic → material id). New harness flags: `--lighting`,
`--pause` (freeze light motion), `--time T` (light animation time), for
reproducible screenshots.

### Texture assertions (carried over from v0.1.3)
- Implemented as specified, in both `src/blocks.cpp` and
  `tools/validate_blocks.py`. The always-on invariance check is gone;
  `--lint` remains. Textures must still be **square** (the per-face quarter
  turns need it), which is the only unconditional pixel requirement.
- `tileable` is checked in exact integer form, `2(n−1)·seam ≤ 3·interior +
  6·lines·(n−1)` per axis, using RGB only. Unit tests cover the boundary
  cases (the limit is inclusive), and C++ and Python agree on all of them.
- **Asserted `tileable`:** brick, grass, dirt, stone, polished, gold. These
  are tileable by construction: wrapping noise lattices, per-pixel hash
  speckle, and wrapped mortar. **Not asserted:** log end/side, furnace faces,
  lamp. Their borders are designed, not wrapping. The log side's furrows
  don't wrap vertically, and it fails the metric narrowly (8.81 vs 8.63).
  **Asserted `invariant`:** every shipped texture (vacuous for the furnace,
  whose `oriented` stabilizers are trivial).
- Fixtures:
  - `tests/blocks_bad/asym_side` now asserts `invariant` on its asymmetric
    side, and is rejected.
  - `tests/blocks_ok/asym_unasserted` uses the same side with no assertion,
    and is accepted.
  - `tests/blocks_bad/seam` asserts `tileable` on a left-to-right ramp, and
    is rejected.

  Validator and loader each have a CTest per fixture.
- The `sandbox_tests` look test now relies on canonical storage. g and g·h
  canonicalize to the same index, so the rendered faces are identical for any
  texture. It also checks that every face's turns come from the lowest-index
  carrying h.

### Choices (PBR / lights)
- **Shared shader math:** `shaders/pbr.glsl` (falloff, F0, GGX, Smith-GGX,
  Schlick, `shadePbr`) is written to be valid GLSL *and* valid C++/GLM.
  `sandbox_tests` includes the same file inside a namespace and tests the
  real shader functions: falloff 0 at d ≥ r, quadratic approach to 0,
  monotonic; F0 = 0, 0.04, 0.16 for reflectance 0, 0.5, 1; metals use the
  albedo; smooth vs rough peak ratio; metal tint.
- **G-buffer pass** writes 5 color attachments (GB0, GB1, **GB2**, GB3,
  **HDR**). The renderer requires `maxColorAttachments ≥ 5`; Vulkan only
  guarantees 4, Intel HD 530 and lavapipe have 8. HDR is cleared to 0 and
  gets the emission. The lighting pass loads HDR and blends ONE + ONE on top.
- **Emission** = the material's `emissive` × the base texture, standing in
  for glTF's emissive texture, so a lamp's pane pattern shows instead of a
  flat white blob.
- **Sun and ambient:** the directional light's radiance is π·E (`sun` = E), so
  a white Lambert face facing it reflects exactly E. Defaults are sun 0.25,
  ambient 0.04, both adjustable. Ambient is a crude IBL stand-in:
  `ambient × (diffuse color + F0)`. Without the F0 term the metal would be
  black outside highlights.
- **Point lights** are camera-relative (rebased in f64) in a per-frame
  host-visible SSBO, bound as a per-frame descriptor set (set 1) of the
  lighting pass. The pass loops over all of them per pixel, brute force. The
  rig has 16 lights:
  - 2 static lamp lights (warm, I = 6, r = 7, at the lamp centers).
  - 6 moving lights orbiting the scene at different radii, heights, speeds
    and directions (I = 4, r = 5).
  - 3 white **key lights** behind the material test row (I = 3, r = 4). Each
    is placed so its mirror reflection off one test block's top points at
    the start camera, so the polished/rough/gold highlights are visible from
    the start view.
  - 5 static fill lights.
- **Heatmap** costs no extra target. The lighting pass writes the number of
  lights covering the pixel into HDR **alpha**, which the additive blend
  accumulates; emission and background write alpha 0. The present pass tints
  any view by it (blue → cyan → green → yellow → red over 0…16). The panel
  shows the same ramp as a legend. In the start view the busiest pixels are
  covered by about 7 lights.
- **AgX** is the widely used minimal fit (Sobotka's inset/outset matrices,
  log2 over [−12.47, +4.03] EV, 6th-order sigmoid polynomial). Its
  display-encoded output is linearized with the exact sRGB EOTF before the
  sRGB swapchain re-encodes it, so the displayed value is exactly AgX's. The
  default exposure is 0 EV (the panel offers ±6).
- **Floor:** a 16×16×1 stone box at z = −1 (block centers x −3…12, y −10…5),
  drawn as **one draw** of `cube::boxVertices(size)`. That is the cube's
  24-vertex layout with UVs in block units, so the repeating stone texture
  tiles once per block and the per-face material lookup still applies.
- **Test blocks:** `polished_stone` (roughness 0.15) and `rough_stone` (1.0)
  share one texture, so only roughness differs. `gold` is metallic 1,
  roughness 0.3. They sit in a row at y = −9 with a lamp at (0, −9); the
  second lamp is at (9, 1). The start camera moved to (5, −15.5, 5.5),
  looking at (5, −3.5, 0).
- F5 gizmos (a cross plus three great circles per light) share the
  debug-line pass with F3/F4.

## v0.1.5 step 0 — third-party verification and security review (2026-10-30)

### Method
- **Pins:** for each `FetchContent_Declare`, checked the repository against
  the project's canonical upstream, and the SHA against `git ls-remote <url>
  refs/tags/<tag> 'refs/tags/<tag>^{}'` (annotated tags peeled).
- **Configure-time scripts reviewed *before* configuring:** each pinned
  commit was cloned into its own scratch directory, with no CMake run, and
  its CMake scripts reviewed there.
- **Fetched trees:** `build/` was then deleted and configured fresh, and
  each `build/_deps/<name>-src` checked with `git rev-parse HEAD` and
  `git status --porcelain`.
- **Compiled code:** the exact set we compile and include came from the
  build itself: `ninja -t commands` for the translation units, plus
  `ninja -t deps`, the compiler's record of every header actually included.
  So the review covers what we build, not each repo's whole tree. That set
  was **pattern-searched**; every hit was then **read in context**. It was
  not read line by line.

### Memory-safety notes (parsers we feed files to)
- **stb_image (PNG path)** is fast and widely used but not hardened against
  hostile input, and it has a history of CVEs. Today it only reads our own
  generated assets and fixtures. **Before user-authored content
  (`data/authored-content`) arrives, PNGs from other players are untrusted
  input:** decode them with a hardened decoder or in a sandboxed process, or
  fuzz this path.
- **nlohmann/json** parses through an explicit state stack, not recursion,
  and destroys values iteratively (since 3.10). It is mature and
  well-fuzzed (OSS-Fuzz). Inputs today are our own definition files.

### Limits of this review
It covers about 180,000 lines by pattern search, with every hit read in
context. That is enough to catch gross problems: network calls, process
spawning, unexpected loads, configure-time downloads, writes outside the
build tree, encoded payloads. It **cannot prove the absence of a subtle,
deliberately hidden backdoor**, for example a memory-safety bug planted in
a parser, logic disguised as ordinary code, or a payload hidden in data
that looks benign. What it does establish is that we build exactly the
upstream commits named, unmodified, and that their configure-time behavior
in our configuration is benign.

### Choices
- **Cells are half-open:** cell (i, j, k) occupies [i, i+1) × [j, j+1) ×
  [k, k+1), so cell (0,0,0)'s *minimum corner* is at WorldPos (0,0,0) and the
  32³ grid spans 0…32. `CellPos` (64-bit) and `cellContaining` /
  `cellCorner` / `cellCenter` live in `coords.h`. `BlockState::air()` uses a
  reserved type id, 0xFFFF.
- **`WorldQuery`** (`world_query.h`): `raycast`, `probe`, `apply(EditSet)`,
  `buildMesh`, `emitters`, `generation`. `DenseGrid` (`grid_world.*`) is the
  only implementation and the only code that knows the dense layout. Callers
  (`main.cpp`, the placement code) hold a `WorldQuery&`. `DenseGrid` itself
  is used directly only for setup, F10 bounds, and the "inside the grid"
  placement check.
- **Raycast** is Amanatides–Woo DDA in grid-local f64. A ray from outside is
  first clipped to the grid box (slab test) and enters through a face,
  including an origin exactly on the far face (x = 32). Exact `tMax` ties step
  x, then y, then z. A ray that *starts inside* a solid cell returns that
  cell at distance 0 with normal (0,0,0): break works, place does nothing
  (there is no face to place against).
- **Mesh:** `buildMesh` bakes each emitted face's texture layer and fully
  turned UV into its vertices: the definition's frame mapping plus the
  stored rotation's turn, the same math v0.1.3's shader did per draw. So the
  G-buffer shader lost its rotation/material-table logic, the rotation SSBO
  is gone, and the material SSBO holds only PBR + emissive. The whole world
  is **one draw**. Each rebuild **replaces** the GPU buffers. The old ones
  are retired with the frame number and freed once `kFramesInFlight` later
  frames have started (their fences have signalled), so there's no
  `waitIdle`. F3 draws a static line buffer of every emitted face's outline,
  built with the mesh, through the line pipeline with a mesh-origin offset.
- **Mesh rebuild cost** (full rebuild after any edit; shown in F1), at about
  4,150 faces: ≈ 4.7 ms in Release (on the build machine, while lavapipe
  shares the CPU), ≈ 13 ms in Debug (unoptimized). That's within a 60 Hz
  frame in Release; it's for the human to judge on the GPU machine.
- **Lights:** v0.1.4's orbiting, key and fill lights are gone. Point lights
  now come only from `emitters()`: the first 16 emissive blocks in
  z, y, x scan order. Each light sits at its block center, colored by the
  normalized emissive, at the v0.1.4 lamp parameters (I = 6, r = 7).
  Placing or breaking a lamp adds or removes its light.
- **Placement rule**, implemented as written in `world/block-orientation`
  for all 11 types (`placement.*`), then canonicalized by
  `BlockRegistry::state`:
  - `uniform`: identity.
  - `column` / `pointed`: local +z along n.
  - `brick` / `pointed-brick` / `twisted-column` / `oriented`: +z along n and
    −y along f.
  - `corner` / `diagonal` / `tetrahedral`: the feature vertex (+x,−y,+z) at the
    clicked face's vertex nearest the hit point.
  - `edge`: the (+z/−y) feature edge at the nearest of the clicked face's
    four edges.

  Each case takes the lowest-index rotation satisfying it.
  - The clicked face's (u, v) uses the texture frames (U = +z on side faces,
    +y on ±z; R = U × n).
  - **f** is the player direction minus its n component, snapped to its
    dominant axis; exact ties prefer x, then y, then z. If the player is
    exactly along n, f falls back to the first of +x, +y, +z perpendicular
    to n.
  - Nearest-vertex ties go to +R/+U; nearest-edge ties follow the order −R,
    +R, −U, +U.
  - Tests check, for every (n, f, hit-region) combination, that the feature
    lands where the rule says. The number of distinct canonical results
    equals each type's orientation count (1/3/6/6/6/12/24/8/4/2/12).
- **Criterion 3's wall clause is superseded (owner's decision,
  2026-10-30):** "a furnace placed on a wall faces out of the wall"
  contradicts the rule. With up along n, a wall furnace lies on its back,
  its top facing out of the wall and its front toward the player,
  perpendicular to n. The owner chose the rule as written. Logs on walls and
  furnaces on floors behave as criterion 3 says. ⇒ `versions.md` criterion 3
  should be reworded to match.
- **Intention layer** (`intentions.*`, table in `bindings.cpp`):
  - Raw GLFW events, plus scripted ones, go through a context stack:
    `gameplay`, with `dev-ui (mouse|keyboard|mouse+keyboard)` pushed while
    ImGui wants that device.
  - The dev-ui context swallows presses of the device ImGui wants.
    **Releases always pass through** to clear held state, but fire nothing.
    Held bindings of a swallowed device stop contributing, so typing into a
    dev window doesn't move the camera.
  - Edge intentions fire on press. Continuous ones (move/ascend/descend/fast,
    primary use held) are sampled from the bindings held at press time.
  - Hands in the table are written main/off (hotbar keys) or left/right (mouse
    buttons) and resolved through handedness.
  - Mouse buttons and the wheel reach the layer only while the mouse is
    captured; releasing the mouse also releases any held buttons. Mouse-look
    stays a raw delta.
- **Hotbars** (`hands.*`):
  - The wheel wraps. **From bare, the first wheel tick returns to the last
    selected slot** (bare isn't a wheel stop); later ticks step from there.
    Number keys for missing slots are ignored.
  - MMB pick selects a matching slot if there is one. Otherwise it replaces
    the selected slot, or, when the hand is bare, the last selected one, and
    selects it.
  - R swaps the two `Hotbar` objects, each keeping its selection.
- **HUD** (ImGui, always on, bottom center): each hand's hotbar with its

  symmetry, canonical index, distance.
- **F6** draws the ray, the hit face's outline, its normal, the hit point,
  and both region partitions the rule reads: quadrants pick the nearest
  vertex, diagonals the nearest edge. The selected vertex and edge are
  highlighted. **F7** shows the context stack, this frame's continuous

- **Tests (`sandbox_tests`):** raycast (axis-aligned, diagonal, through

  edit apply and generation; mesh face culling (1 block → 6 faces, adjacent

- **Revisions after the first build (owner, 2026-10-30):** reach is **12**

`MomentOIT.hlsli` / `MomentMath.hlsli`, read, not run; the ZIP's SHA-256 is
3a09c53b…c55c1fc).
- **What the paper defines:**
  - Absorbance A(z) is "the cumulative distribution function of the finite
    measure Z := Σ −ln(1−α_l)·δ_{z_l}".
  - The stored vector is b := E_Z(b) with b(z) = (1, z, …, z^m) in
    log-warped depth on [−1, 1] (§3.3), and b0 is the total absorbance.
  - Reconstruction (Algorithm 1) works on b/b0. The moment problem it relies
    on needs only a finite non-negative measure; nothing requires Diracs.
- **Our measure is σ·dl along the ray,** non-negative because σ ≥ 0. Its
  moments in warped depth are ∫σ·w(r)^k dr = Σ ∓σ·F_k(r) over the boundary
  crossings, with F_k the closed-form antiderivative of w^k. So the
  boundary-integral moments are *exactly* moments of a valid measure, the
  input the reconstruction assumes. **The proposal holds; no decision
  needed.**
- **Two precisions on the spec, recorded rather than changed:**
  - **"z" must be eye *distance* along the ray, not view-space depth.** Only
    in ray distance does Σ ±σ·r equal σ × path length; view depth would
    undercount by cos θ toward the screen edges. The warp is applied to r.
    The paper warps view depth, but any monotone depth coordinate along the
    ray works, provided accumulation and queries use the same one.
  - **Colored absorption isn't in the paper,** which uses a scalar α.
    Choice: total absorbance is stored **per channel** (RGB), exact for
    Beer–Lambert. **One** set of moments, from the mean σ, gives the depth
    *shape* of transmittance, scaled per channel. This is exact for any
    single tint and an approximation where differently colored media mix
    along a ray.

### Choices
- **Meshing** (`grid_world.cpp`):
  - Translucent cells go to a separate mesh, one face per cell side,
    wherever the neighbor isn't the same block type (the group). Opaque
    faces next to translucent cells are emitted.
  - `emitters()` includes translucent blocks with emission: the glow block
    is a lamp-like light colored by its emission (the occlusion artifact is
    accepted per the spec).
  - Translucent blocks are solid for the raycast.
- **Absorbance pass** (`absorbance.frag`): cullMode NONE, no depth test,
  additive into **B0** (RGBA32F: rgb per-channel totals, a = scalar) and
  **moments** (RGBA32F: b1..b4).
  - Each fragment uses its eye distance r, clamped to the opaque surface on
    the same pixel ray: r_opaque = r · z_lin(opaque) / z_lin(fragment).
    Both points lie on one ray, so this needs only near/far, not an inverse
    matrix.
  - F_k is taken relative to the translucent near bound, with r clamped to
    [0.05, 128] (fixed harness constants).
  - The math lives in `shaders/oit.glsl`, which is valid GLSL and C++: the
    warp, F_k, the boundary term, and the authors' 4-power-moment
    reconstruction, ported verbatim. My only change: the *normalized*
    absorbance is clamped to [0, 1] and returned, so transmittance can be
    computed per channel.
- **Shading pass** (`translucent.frag`): cullMode BACK, depth-tested in the
  shader against the opaque depth (read-only, as the lines pass does).
  - Translucent surfaces are **specular-only dielectrics** (their volume
    absorbs and they have no diffuse albedo) plus front-face emission. They
    use the same `shadePbr` and light loop as opaque surfaces, attenuated by
    T_c = exp(−B0_c · A_norm(r)).
  - The result is accumulated additively in an **RGBA32F** target. fp16
    addition is order-dependent enough to matter here.
  - Translucent blocks need a texture (the format requires one per orbit),
    but the shading doesn't use it yet.
- **Composite** happens in the present pass before AgX:
  C = C_opaque · exp(−B0) + accumulated.
- **Moment bias default is 5e-4, not the paper's single-precision value.**
  The paper's value (from memory of Peters et al. 2017; the supplementary's
  bias table wasn't extractable) gave up to **4/255 differences between face
  orders**. Boundary-integral moments are sums of large ±σ·F_k(r) terms that
  cancel, so they carry more rounding than the paper's direct sums, and the
  reconstruction's root-vs-depth tests then flip with summation order.
  Measured at the capture view (max difference across orders / pixels
  differing):

  | Bias | Max difference | Pixels |
  |---|---|---|
  | 5e-7 | 4/255 | 423 |
  | 5e-5 | 1/255 | 5 |
  | 1e-4 | 1/255 | ≤ 3 |
  | 5e-4 | 0 | 0 |

  Raising the bias from 5e-5 to 5e-4 changes the image by at most 5/255, in
  0.7% of pixels. The bias stays tunable in the F9 panel and via
  `--moment-bias`. β (overestimation) = 0.25, the paper's value.
- **Glass σ** (per block): red (0.03, 0.55, 0.65), green (0.6, 0.04, 0.5),
  blue (0.65, 0.45, 0.03). That's roughly 50–95% per-channel transmission
  per block, so stacks of 1–4 read as tints rather than smoke. Glow emission
  is (3.0, 2.4, 1.2), with no absorption. Roughness 0.08.
- **Readbacks:**
  - `--capture` copies the swapchain image after the UI pass; the swapchain
    gained `TRANSFER_SRC`, and the graph gained a `transferSrc` resource use.
  - `--check-absorbance` copies one B0 texel.
  - Both use host buffers read after the frame's fence. The PNG writer
    (`png_write.*`) uses stored deflate blocks, so it needs no zlib.
- **Face order:** applied to the translucent index buffer at mesh build
  (`translucency.*`), whole faces at a time.
  - Forward/reverse sort by face-center distance from the camera at build
    time.
  - Shuffle is Fisher–Yates on `std::mt19937_64(seed)` with our own
    reduction, so it's portable.
  - Changing the order in the F9 panel re-uploads the mesh.
- **Carry-overs:**
  - `apply` returns `ApplyResult {changed, rejected}`; out-of-bounds edits
    are rejected and leave the grid and its generation untouched. Placement
    no longer asks `DenseGrid` anything. `DenseGrid::contains` is private.
  - The CTest `grid_confined_to_setup` fails if anything outside
    `grid_world.*`, or outside `main.cpp`'s setup and F10 lines, names
    `DenseGrid` or includes `grid_world.h`.
  - The HUD shows hotbars, button actions and the target's *name*. The F6
    window shows cell, face, canonical orientation and distance.

**Why the glass reads like smoke (owner's observation):** we render only the
volume (absorbance) plus a specular-only surface lit by point lights and
the sun. Real glass is recognized mostly by its *surface*: Fresnel
reflection of the environment, strongest at grazing angles, and visible
edges or frames. We have no environment to reflect yet (no IBL/SSR), so the
specular term only shows small point highlights, and the face texture is
loaded but unused. Cheap ways to give it a surface later, each a small,
reversible change: a Fresnel-weighted ambient/sky reflection term; using
the face texture (its frame and alpha) as a faint surface color or
emission; or edge darkening.

F1 fix: pass names are padded to 12 characters (was 10, so "translucent",
at 11, pushed its number one column right).

### v0.1.6 follow-up: connected-glass frames (2026-10-30)
The owner noted that the glass read like "vague solidified smoke". The
volume was correct, but the glass had no visible surface. So absorbing
translucent faces now carry a **connected-glass frame**: a procedural
surface layer.
- **Where:**
  - **Bits 0–3:** the mesher (`DenseGrid::frameBits`) gives each translucent
    face 4 edge bits (−R, +R, −U, +U). An edge is framed unless the in-plane
    neighbor is the same type with an identical face toward the same normal,
    i.e. unless the region's surface continues flat across it. So a run of one
    tint is framed only along its outline and creases, as in "connected glass".
  - **Bit 4** (surface layer on): set against air, and against a different
    translucent type only when this face's type id is lower, so an interface
    pair is framed once. Never set against opaque cells.
  - The glow block (no absorption) gets no frame.
  - Translucent vertices reuse `uv` for face-frame coordinates and `layer`
    for the bits; translucent surfaces have no texture.
- **What:** a band 1/16 block wide with coverage 0.85 (`shaders/oit.glsl`,
  `glassFrameCoverage`, unit-tested with the mesher's bits).
  - **Absorbance pass:** the band adds a surface absorbance −ln(1 − 0.85) at
    the face's own depth to the totals and moments. That's the paper's
    original per-surface term, so it commutes like the volume terms; it is
    skipped behind the opaque surface.
  - **Shading pass:** coverage × the lit color of a **neutral** pale grey
    (0.7) dielectric at roughness 0.6, attenuated by T like everything else.
  - **No tint in the surface (owner's direction):** the volume already tints
    correctly, so the surface carries only surface attributes.
- **Known limitation:** back faces are culled in the shading pass, so a
  pane's far-side frame darkens what's behind it (its coverage is in the
  absorbance) but isn't lit, and it reads as a darker line through the
  glass.
- **Toggles:** "glass frames" in the F9 panel, `--no-glass-frames`.
  `--check-absorbance` turns frames off, because it checks the volume
  integral.
- **Results:** order invariance with frames on is max 1/255 (≤ 5 pixels)
  across forward/reverse/3 shuffles. The absorbance check passes. Debug
  15/15 `ctest`; the headless suite passes with zero validation errors.

### v0.1.6 fix: material-table stride (2026-10-30)
Reported by the owner: lamp faces had stopped glowing, though they still
lit their surroundings. **Cause:** v0.1.6 grew `GpuMaterial` to 64 bytes
(adding absorption and translucent emission), but `gbuffer.frag` kept its
own 32-byte `Material` struct. So the G-buffer pass indexed the table at
the wrong stride. Opaque emission, and the GB2 roughness, metallic and
reflectance, came from the wrong entries; the gold and polished blocks
were affected too. Point lights come from `emitters()` on the CPU, so
those were unaffected. **Fix:** a single `shaders/material.glsl` struct,
included by every shader that reads the table, with the C++
`static_assert` naming it, so the layouts can't drift apart again.
Verified on lavapipe: lamp faces glow with their pane pattern again, and
the roughness view shows the per-material values. ctest, the absorbance
check and order invariance still pass.

### Choices
- *(The variant-set, edge-matching, seam-tolerance, wang-generation and
  `wang.glsl` bullets below describe the first build; see "Revision:
  variant sets, three rules" at the end of this section for what replaced
  them.)*
- **Variant-set format.** A texture entry is a file name (a 16×16 PNG) or
  `{ "wang": file }` / `{ "connected": file }`, a **64×64 atlas of 16 tiles**
  (tile i at column i % 4, row i / 4), one file per set rather than 16. Tile
  index = edge bits in the image's own frame, N = 1 (top row), E = 2, S = 4,
  W = 8. The loader appends a set's 16 tiles as consecutive layers; a face's
  layer is tile 0. A set takes no assertions (wang edges are always checked).
- **Edge matching** (`seamMatches(first, second, axis)`): the existing
  integer seam metric applied to `first`'s last column/row against
  `second`'s first, with the interior mean taken over both images, so
  `seamIsTileable(img)` is exactly `seamMatches(img, img)` on both axes. A
  wang set is checked for every ordered pair of tiles whose touching edges
  share a label, horizontally and vertically (256 seams per axis family).
- **Seam tolerance at 16 px: 1.5× → 2×** (the spec asked to re-check it).
  At 16 px a seam mean rests on 16 samples, and wang matching takes the
  worst of 256 seams; per-pixel speckle alone (no real seam) reached 1.73×
  the interior mean on dirt and grass across five seeds (stone 1.34×);
  with the final per-texel tiles, up to 1.74× (dirt), 1.63× (stone). At
  2× the shipped sets pass with ≥ 13% margin; the fixtures fail by far
  (`seamed` 99.9 vs limit 14.3; `wang_mismatch` 120.9 vs 29.4). Boundary
  cases in `testSeamMetric` were recomputed for 2×.
- **Wang generation** (`gen_block_texture.py`; revised after the owner's
  GPU check, 2026-11-04): every tile is **independent per-texel noise**,
  hashed with its own index. No feature is larger than a texel, so any tile
  meets any other without a seam (the edge check still runs and passes),
  and nothing repeats at the block period. The first version composed
  low-frequency fields (a shared periodic base, label-keyed edge bands
  tapered to a common corner, a per-tile interior) so features like stone's
  veins crossed edges; the owner saw a visible 1-block pattern on the GPU,
  and measuring confirmed it: 24–40% of each set's variance was identical at
  the same texel in every tile (chance: 6%), from the shared base and the
  identical corners. Owner: don't overcomplicate it; natural blocks need no
  corner or edge structure. Now 6–7%. Stone lost its veins.
- **Brick** stays a 4-fold pinwheel bond (10×6 bricks round a 4×4 centre),
  now 16 px, shifted 3 texels so the wrap seam runs through bricks: a
  uniform block's faces are turned by their transversals, and a running
  bond would show sideways on some faces. (Asymmetry is allowed now, but a
  sideways bond would look wrong.) No other texture is symmetrized any more.
- **Texel position from the fragment's position, not a vertex UV.** The
  vertex is now `{pos, normal, layer, material, texInfo}` (texInfo: turn in
  bits 0–1, set kind in 2–3), shared by opaque and translucent faces with
  no repurposed fields. `shaders/block_texture.glsl` derives the in-face
  coordinate from the mesh-relative position (mesh origins are on the
  lattice) along the face frame, turns it per cell (a 90° turn about a cell
  centre maps the lattice to itself, so it commutes with `fract`), and gets
  the cell from `floor(pos − n/2)`. The texel and the cell come from the
  same value, so they always agree at edges, and a quad spanning several
  cells samples per cell (criterion 4).
- **`shaders/wang.glsl` is GLSL and C++** (like `pbr.glsl`): the face frame,
  the edge hash (lowbias32 over the doubled edge midpoint and the plane's
  axis), the turn mapping (image edge e sits at face position (e − turn)
  mod 4). The fragment shader, the mesher (connected tiles), the ghost
  builder and the tests all run this one file. The G-buffer push constant
  carries the mesh origin's cell for hashing.
- **Ghosts resolve their wang tile on the CPU** (one cell each, same code),
  so the translucent passes, whose push constants are at the 128-byte
  minimum, need no origin. Connected glass needs none either: the mesher
  resolves its tile.
- **Connected frames:** the mesher maps `frameBits` (face frame, + surface
  bit) to a tile with the turn applied; no surface layer → tile 0. The
  translucent passes take coverage = the tile's alpha and the frame colour
  from the texture. `--no-glass-frames` sets coverage 0, which is what
  tile 0 is. The procedural band, its constants and its test are gone.
- **Sampling:** a linear, mipmapped, clamp-to-edge sampler with 16×
  anisotropy where the device has `samplerAnisotropy` (re-selected with the
  feature required, since this vk-bootstrap has no "if present"); the
  shader does anti-aliased nearest with `textureGrad` on the continuous UV,
  so mip selection and anisotropy see the true derivatives. Clamp-to-edge
  keeps the one-pixel AA blend from wrapping to the opposite edge of a tile.
- **Mips** are built on the CPU at load (`buildMipChain`), 2×2 box filter in
  linear light, alpha linear: 5 levels, the 1×1 the face's mean colour.
- **No PBR maps exist yet** (roughness/metallic are per-material
  constants), so "PBR maps are 16×16" has nothing to apply to.
- **Variant view:** F2 view 7. The G-buffer pass writes the tile index as a
  colour (sets) or grey (no set) into GB0 when the push constant asks, and
  present shows GB0. Opaque faces only; glass draws over it as usual.
- **Test scene:** the ground's top layer is stone (x 0–9) and dirt
  (x 10–19) over y 0–7; a wall along y = 31, z 16–23, of stone, dirt and
  grass (10 wide each), which also stands behind the glass as a lit wall.
- **Merged-quad test:** `--merged-quad` replaces the 16 top faces of stone
  cells x, y 2…5 with one quad (`mergeTopFaces`); the headless suite
  compares it with the unmerged capture.
- **Glass σ** retuned as specified (blue [2.2, 1.2, 0.15], green
  [2.0, 0.15, 1.8], red [0.15, 1.9, 2.2]).
- **C/V:** `Camera::up() = right × forward`; the camera moved into
  `sandbox_core` so the test can drive it.
- **Container patch:** `ContainerState::patch` (N) and `consume`. Picks walk
  the N×N patch in scan order (rows along U, then R); in order continues the
  cursor cell by cell (draws + cells placed so far), random picks hash
  (cell, id, draws) with draws fixed for the patch. With `consume` each
  placed block decrements a copy of its slot's count, count-weighted
  weights by what's left at that cell, emptied types drop out, and cells
  past the end go to `PlannedEdit::unaffordable` (amber outlines in the
  preview). `afterCommit` advances draws by the blocks placed and, when
  consuming, uses up the real counts. The consume toggle is in F8 and
  `--consume`, since it is the only way to see the amber marking.
- **Hotbar icons:** each block slot shows its local −y face (furnace: the
  front) via one ImGui texture per array layer (2D view, mip 0,
  `ImGui_ImplVulkan_AddTexture(view, layout)`: this ImGui's API takes no
  sampler), drawn between the backend's `DrawCallback_SetSamplerNearest` /
  `…Linear` callbacks, at 16 × 3 × DPI points. Connected sets show the
  fully framed tile over a rectangle of one block's transmittance. Tools
  show P / W / S / C. The selected slot's name (or `bare`, centred on the
  bar) is drawn above it on the foreground list, clamped to the screen.

### Revision: variant sets, three rules; the engine checks structure only (owner, 2026-11-04)
After the GPU check, the owner and assistant worked backwards from block
kinds and player goals (`render/block-textures`, "three principles"):
variant selection breaks up repetition; edge matching is only for coherent
small features that cross edges, and only on the edges they cross;
distinctive features are block content, not rendering.
- **Format:** `{ "random": file, "tiles": n }` (1–32), `{ "matched": file,
  "edges": "ns" | "nsew" }` (4 or 16 tiles), `{ "connected": file }` (16).
  Atlases are 64 wide, 4 tiles per row, 16 × ⌈n / 4⌉ high. The four-edge
  case is Wang tiling (hashed labels after Wei 2004); `ns` is matching
  along one axis only, so it isn't called Wang.
- **The engine checks structure only:** sizes, and a set's atlas has exactly
  the rows its tile count needs. Removed: the `tileable` assertion (and the
  `asserts` field), the seam metric (`seamMatches`, `seamIsTileable`), wang
  edge matching (`checkWangSet`), the connected-set "tile 0 transparent"
  check, `testSeamMetric`, the `seam` and `wang_mismatch` fixtures. The
  2× tolerance question is moot. New fixture: `wrong_tiles` (a 16-tile atlas
  declared `matched` ns).
- **Content:** dirt, grass, stone `random` 8 (per-texel noise); stone brick
  (new) `random` 4 (one dressed stone per face in a one-texel mortar border,
  tiles differing by a small tint shift and chipped arrises); log bark
  `matched` ns 4 (column-wise grain, label bands at N/S fading over 6
  texels with the two seam rows pure band, so continuity holds by
  construction; columns independent, so E/W edges are breaks); gravel (new,
  soft) `matched` nsew 16 (pebbles of radius 1.4–2.4 per (axis, label)
  centred on the seam at 4.5–11.5 along it, so corners are plain grit; three
  interior pebbles per tile). Log ends stay single. Gravel and stone brick
  replace grass and brick on the main hotbar (slots 3, 4).
- **`shaders/variants.glsl`** replaces `wang.glsl`: `randomTile(cell, n,
  count)` hashes cell and face id; `matchedTile(cell, n, turn, nsew)` hashes
  only the declared image edges (ns: N | S << 1). `texInfo` is now turn
  (bits 0–1), kind (2–4: none, random, matched ns, matched nsew,
  connected), random count − 1 (5–9). Translucent faces resolve random and
  matched tiles on the CPU in the mesher (`resolvePositional`), like ghosts,
  so the translucent passes never hash; opaque faces hash per fragment.
- **A/B switches for the G-buffer timing:** `--anisotropy N` (1 = off) and
  `--no-variants` (random and matched faces show tile 0).
- **Tests:** `testVariantSelection` (pinned values for random, ns, nsew,
  checked against an independent Python implementation; random in range,
  every tile used, face-dependent; matched agreement across declared edges
  on all six normals and four turns; ns = nsew's N and S labels; the CPU
  path resolves the same layer); `testParseDefinition` (the three rules and
  their malformed forms; `asserts` is an unknown field; atlas sizes);
  `testVariantSets` (split of any count, tile counts).
